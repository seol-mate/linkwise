# 2026-11-25 작업 기록

## 1. Google 로그인 실패 원인 분석과 계정 연결 (`90ae716`)

### 원인
- Google 로그인이 실패했고 dev 서버 로그에 `[auth][error] OAuthAccountNotLinked`가 찍혔다.
- Google 인증은 성공했지만, 같은 이메일의 기존 사용자(GitHub로 먼저 가입)가 있어 Auth.js 기본 동작으로 계정 연결이 거부된 것이다. `redirect_uri_mismatch` 등 Google 설정 문제는 아니었다.
- 어느 provider로 만든 사용자인지는 DB를 조회해 확인하지 않았다(추정).

### 해결
- Google provider에만 `allowDangerousEmailAccountLinking: true`를 적용했다 (`src/auth.ts`).
- Google은 이메일 소유를 검증하므로 위험이 비교적 작다. 다른 provider에는 켜지 않는다.
- 결과: GitHub로 가입한 계정에 Google 로그인은 연결되지만, 반대로 Google로 가입한 계정에 GitHub 로그인은 여전히 막힌다.
- 실제 로그인으로 정상 동작 확인(사용자 확인).

## 2. 로그인 에러 문구 세분화 (`7b98ff1`)

## 3. 게스트 정리 단위 테스트 (`a70e689`)
- `__tests__/users.test.ts` 10개 테스트 (`userExists`, `deleteStaleGuests`).
- 실제 DB 대신 `drizzle-orm/pg-proxy`로 생성된 SQL과 파라미터를 가로채 검증한다. `.env.local`의 `DATABASE_URL`이 실제 Neon일 수 있어 삭제 로직을 진짜 DB로 돌리지 않기 위함.
- 검증: 게스트 이메일 접미사 + `created_at < cutoff` AND 결합(OR 없음), 오래된 순 최대 100명, `limit` 인자, 삭제 수 반환, DB 오류 전달.
- 조건을 일부러 `lt`→`gt`로 바꿔 테스트가 실패하는 것을 확인(변이 검증)한 뒤 복구.
- 한계: SQL 문자열만 검증하며 DB가 실제로 행을 지우는지는 확인하지 않는다(테스트용 DB 필요).

## 4. `/login` prerender 에러 조사 (코드 변경 없음)
- dev 로그에 `Route "/login": ... crypto.getRandomValues() while prerendering` 에러가 계속 찍힌다.
- `npm run build`는 성공(컴파일, 타입 체크, 정적 페이지 6/6)하고 `/login`은 `◐ Partial Prerender`로 정상 → **dev 모드 전용 로그이며 배포를 막지 않는다.**
- 우리 코드에서 렌더링 중 `crypto`를 호출하는 곳은 없다(`createGuestEmail` 기본 인자는 게스트 로그인 시에만 실행). 라이브러리 내부 호출로 추정되지만 원인은 특정하지 못했다.
- 이번 변경을 stash해도 같은 에러가 나서 이전부터 있던 문제임을 확인.

## 5. AI 요약/태깅 비동기 처리 점검 및 중단 수집 복구 (`5639f71`)

### 점검 결과
- 비동기 처리는 **이미 구현돼 있었다**: 저장은 즉시 끝내고 `after()`로 응답 뒤에 수집·요약, `AutoRefresh`가 약 35초간 목록 갱신, 실패 시 "다시 시도" 가능. 로드맵의 "(비동기 처리)"는 새로 만들 게 없었다.
- 빈틈: 함수 시간 초과나 프로세스 종료로 수집이 끊기면 북마크가 영원히 `pending`으로 남고, 재시도는 `failed`일 때만 가능해 복구 수단이 없었다.

### 변경
- `src/lib/stale.ts`(신규): `STALE_PENDING_MS = 10분`, `stalePendingCutoff`, 안내 문구. 10분은 AI 요약 최악 소요(60초 × 3회)보다 길게 잡은 값.
- `src/lib/bookmarks.ts`: `failStalePendingBookmarks(userId, cutoff)` — 본인의 오래된 `pending`을 `failed`로 바꾸고 "수집이 중간에 중단되었습니다. 다시 시도해 주세요." 저장.
- `src/app/bookmarks/page.tsx`: 목록 조회 전에 호출. 실패해도 목록 표시는 막지 않는다.
- 늦게 끝난 원래 작업이 `saveSummary`로 `done`을 덮어쓰면 정상 상태로 복구된다.
- `__tests__/stale.test.ts` 6개 테스트(pg-proxy). `pending`→`done`으로 조건을 바꿔 실패하는 것을 확인.

### 하지 않은 것
- `maxDuration`: Next 문서상 `after()`는 라우트의 `maxDuration` 안에서만 실행되고, 서버 액션은 페이지 단위로 설정한다. 배포 플랫폼/요금제를 몰라 값을 정하지 않았다.
