## 게스트 데이터 보관 기간과 자동 정리

게스트 계정이 쌓이지 않도록 7일이 지난 게스트를 삭제한다.

### 동작
- 보관 기간: `GUEST_RETENTION_DAYS = 7` (`src/lib/guest.ts`). `guestCutoff(now)`가 기준 시각을 계산.
- **정리 시점**: 게스트 로그인(`authorize`) 직전에 `deleteStaleGuests(guestCutoff())` 실행 (`src/auth.ts`). 정리가 실패해도 로그인은 막지 않고 에러 이름만 로그로 남긴다.
- **삭제 로직** (`src/lib/users.ts`, 신규):
  - 이메일이 `@guest.linkwise.invalid`로 끝나고 `createdAt < cutoff`인 사용자만 대상.
  - 오래된 순으로 한 번에 최대 100명(`DEFAULT_CLEANUP_BATCH`)만 삭제 → 로그인 지연 제한.
  - bookmarks/tags/accounts는 FK `onDelete cascade`로 함께 삭제.
- **삭제된 게스트의 세션 처리** (`src/lib/session.ts`): 게스트 이메일인 경우에만 `userExists(id)`를 조회, 없으면 로그아웃 상태(`null`)로 취급. 일반 사용자는 추가 조회 없음.
- **안내 문구** (`src/app/login/page.tsx`): "...7일 후 삭제됩니다."

### 남은 확인
- `deleteStaleGuests`(DB 의존)는 단위 테스트가 없다. 필요하면 DB 모킹/통합 테스트 추가.
- 정리가 로그인 시점에만 일어나므로, 게스트 로그인이 없으면 만료 데이터가 남는다. 필요 시 cron 방식 검토.
