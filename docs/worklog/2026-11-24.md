## 1. 게스트 데이터 보관 기간과 자동 정리 (`36fff4d`)

게스트 계정이 쌓이지 않도록 7일이 지난 게스트를 삭제한다.

### 동작
- 보관 기간: `GUEST_RETENTION_DAYS = 7` (`src/lib/guest.ts`). `guestCutoff(now)`가 기준 시각을 계산.
- **정리 시점**: 게스트 로그인(`authorize`) 직전에 `deleteStaleGuests(guestCutoff())` 실행 (`src/auth.ts`). 정리가 실패해도 로그인은 막지 않고 에러 이름만 로그로 남긴다.
- **삭제 로직** (`src/lib/users.ts`, 신규):
  - 이메일이 `@guest.linkwise.invalid`로 끝나고 `createdAt < cutoff`인 사용자만 대상.
  - 오래된 순으로 한 번에 최대 100명(`DEFAULT_CLEANUP_BATCH`)만 삭제 → 로그인 지연 제한.
  - bookmarks/tags/accounts는 FK `onDelete cascade`로 함께 삭제.
- **삭제된 게스트의 세션 처리** (`src/lib/session.ts`): 게스트 이메일인 경우에만 `userExists(id)`를 조회, 없으면 로그아웃 상태(`null`)로 취급. 일반 사용자는 추가 조회 없음.
- **안내 문구** (`src/app/login/page.tsx`): "...7일 후 삭제됩니다."

## 3. Google 로그인 및 로그인 버튼 아이콘 (`6f568a3`)
- `src/auth.ts`에 Google provider 추가, `signInWithGoogle` 액션(`src/app/actions/auth.ts`), 로그인 페이지에 "Google로 계속하기" 버튼.
- `.env.example`에 `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` 추가, README 로드맵 체크.
- 로그인 버튼 아이콘: `src/components/icons/google-icon.tsx`, `github-icon.tsx`.
  - Google: Google 브랜딩 가이드의 공식 G 로고 SVG(path·색 수정 없음).
  - GitHub: GitHub Brand Toolkit의 Invertocat SVG(path 수정 없음). 로고 정책상 흰색/검정만 사용해 라이트 모드는 흰색, 다크 모드는 검정 로고를 쓴다.
- 직접 해야 했던 설정: Google Cloud Console에서 OAuth 클라이언트 생성, 리디렉션 URI(`/api/auth/callback/google`) 등록, `.env.local`에 키 입력.

### 메모
- 공식 "Sign in with GitHub" 버튼 규격은 없다. Google은 웹에서 Identity Services가 만든 버튼만 허용한다는 안내가 있어, 앱 인증 심사 전에 [브랜딩 가이드](https://developers.google.com/identity/branding-guidelines)를 직접 확인해야 한다. (검색 요약만 확인, 원문 미확인)
- WSL의 `/mnt/c`에서는 dev 서버가 파일 변경을 감지하지 못하는 경우가 있다. 코드를 고쳐도 화면이 안 바뀌면 `.next`를 지우고 서버를 재시작한다.
