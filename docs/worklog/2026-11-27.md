# 2026-11-27 작업 기록

## 1. 북마크 목록 조회 시에도 만료된 게스트 정리 (`ce8770a`)

### 배경
- 11-24 기록의 남은 과제. 게스트 정리가 게스트 로그인 시점에만 실행되어, 게스트 로그인이 없으면 7일이 지난 데이터가 계속 남았다.
- cron은 배포 환경이 정해지지 않아 보류하고, 앱 안에서 정리할 수 있는 시점을 하나 더 만들었다.

### 동작
- `/bookmarks` 페이지에서 응답 뒤 `after()`로 `cleanupStaleGuestsThrottled()`를 실행한다. 목록 표시를 늦추지 않는다.
- 매 요청마다 DELETE를 보내지 않도록 **인스턴스당 1시간에 한 번**(`GUEST_CLEANUP_INTERVAL_MS`)만 실행한다. 게이트는 통과 시각을 먼저 기록하므로 동시 요청 중 첫 번째만 실행된다.
- 정리는 throw하지 않고 에러 이름만 로그로 남긴다. 실패하면 다음 간격까지 다시 시도하지 않는다.
- 게스트 로그인 시점 정리는 같은 `cleanupStaleGuests()`를 쓰도록 정리했다(간격 제한 없음, 동작 동일).

### 변경 파일
| 파일 | 내용 |
| --- | --- |
| `src/lib/interval-gate.ts` (신규) | `createIntervalGate(intervalMs)` — 간격 안의 중복 실행 차단 |

| `__tests__/guest-cleanup.test.ts` (신규) | 12개 테스트 (게이트 경계값, 동시 요청, 실패 시 로그, 간격 제한) |

- 게이트 조건을 `<`→`<=`로 바꿔 테스트 3개가 실패하는 것을 확인(변이 검증)한 뒤 복구.

### 한계
- 게이트 상태는 인스턴스 메모리에만 있다. 서버리스에서 인스턴스가 여러 개면 각자 1시간에 한 번씩 실행된다. 한 번에 최대 100명만 지우고 대상이 없으면 바로 끝나서 부담은 작다.
- 아무도 접속하지 않으면 여전히 정리되지 않는다 → 배포 환경 결정 후 cron.
- 실제 DB에서 행이 삭제되는지는 확인하지 않았다(단위 테스트는 `deleteStaleGuests`를 가짜로 대체).
